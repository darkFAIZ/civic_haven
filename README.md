# CivicHaven

CivicHaven is a Flutter mobile app for personal and community safety. It lets a user create an account, save safety activity, submit incident reports with evidence, find a safer route, scan documents or images, open emergency resources, and keep a personal history.

This repository contains the Flutter app in `civic_haven/`. Firebase is required for account creation, sign-in, user profiles, history, and uploaded evidence.

The AI Guide uses Firebase AI Logic with Gemini. No Gemini API key is stored in the Flutter app.

## Main features

- Email and password account creation and sign-in.
- Email verification for newly created accounts.
- Home dashboard with safety resources and emergency links.
- Safe Route page using the device's current location and an external maps app.
- Incident reports with category, location, details, severity, camera evidence, and file attachments.
- Trust Scan page for checking an image or document.
- AI Guide page for in-app safety guidance.
- Profile and saved activity history stored per user.
- Emergency phone links opened through the phone's dialer.

## Requirements

Install the following before running the app:

1. Flutter SDK (this repository includes a local Flutter SDK in `flutter/`, but a system Flutter installation also works).
2. Dart SDK included with Flutter.
3. Android Studio and an Android SDK for Android development.
4. A USB cable or an Android emulator for testing on Android.
5. macOS with Xcode for building or installing on an iPhone. iOS builds cannot be created on Windows.
6. A Firebase account and a Firebase project.

Verify the Flutter installation from the `civic_haven` folder:

```powershell
flutter doctor
flutter pub get
```

If `flutter` is not in your PATH, use the Flutter executable in the repository instead:

```powershell
..\flutter\bin\flutter.bat doctor
..\flutter\bin\flutter.bat pub get
```

## Configure Firebase

The checked-in Firebase configuration may contain placeholder or project-specific values. Configure your own Firebase project before trying to create an account or upload data.

### 1. Create the Firebase project

1. Open the [Firebase Console](https://console.firebase.google.com/).
2. Select **Create a project** or open an existing project.
3. Give the project a name, for example `civichaven-mobile`.
4. Analytics is optional for this app.

### 2. Enable Authentication

1. In Firebase Console, open **Build > Authentication**.
2. Select **Get started**.
3. Open the **Sign-in providers** tab.
4. Enable **Email/Password** and save.

The app currently implements Firebase email/password authentication. This is not Google OAuth sign-in; no Google Sign-In provider is implemented.

### 3. Enable Gemini for the AI Guide

1. In Firebase Console, open **AI Services > AI Logic**.
2. Enable the Gemini Developer API for the project and accept the requested terms.
3. Keep the app signed in with Firebase Authentication before opening **AI Guide**.

The Android app uses Firebase AI Logic's Gemini Developer API backend. For a public release, configure Firebase App Check in the Firebase Console and initialize it before using the AI Guide.

### 4. Create Firestore

1. Open **Build > Firestore Database**.
2. Select **Create database**.
3. Choose a location close to your users.
4. Use **Test mode** only for initial development.

The app writes to these paths:

```text
users/{userId}
users/{userId}/history/{historyId}
```

Before production, replace test-mode rules with rules that require authentication and limit each user to their own documents.

### 5. Create Storage

1. Open **Build > Storage**.
2. Select **Get started** and choose the same region where appropriate.
3. Use test rules only while developing.

Evidence is uploaded under:

```text
users/{userId}/report-evidence/{timestamp}_{fileName}
users/{userId}/scan-evidence/{timestamp}_{fileName}
```

Storage rules should require an authenticated user and restrict access to that user's `users/{userId}/` folder before production use.

### 6. Connect Flutter to Firebase

From the `civic_haven` project folder, install and run FlutterFire CLI:

```powershell
dart pub global activate flutterfire_cli
flutterfire configure
```

When prompted:

1. Sign in with the Google account that owns the Firebase project.
2. Select the Firebase project.
3. Select **Android**. Select **iOS** too when configuring on a Mac.
4. Confirm the Android package name `com.example.civic_haven` if prompted.
5. Let FlutterFire update `lib/firebase_options.dart` and create the platform Firebase files.

Run this command again whenever you add a new Firebase platform or switch projects. Do not manually invent Firebase API keys or edit the generated options file by hand.

### 7. Check Android fingerprints when needed

The current app does not use Google OAuth, but fingerprints are required if Google Sign-In or another Google API is added later. Generate the debug fingerprints with:

```powershell
cd android
./gradlew signingReport
cd ..
```

Add the SHA-1 and SHA-256 values in **Firebase Console > Project settings > Your apps > Android app**.

## Run the app during development

1. Connect an Android phone with Developer options and USB debugging enabled, or start an Android emulator.
2. From the project folder, check that Flutter can see the device:

```powershell
flutter devices
```

3. Install dependencies and run the app:

```powershell
flutter pub get
flutter run
```

4. Create an account with an email address and a password of at least six characters.
5. Open the verification email and verify the account.
6. Sign in again and test location, camera, file selection, reports, and Firebase history.

On the first use of camera or location, accept the permissions requested by the operating system. A physical phone is recommended for testing camera, GPS, phone calls, and external maps because an emulator may not provide realistic sensor behavior.

## Install on an Android phone

### Option A: Direct development install

This is the fastest option for a personal phone:

1. Enable **Developer options** and **USB debugging** on the Android phone.
2. Connect the phone by USB and accept the debugging authorization prompt.
3. From `civic_haven`, run:

```powershell
flutter devices
flutter pub get
flutter run
```

Flutter builds and installs a debug version on the selected phone.

### Option B: Build and share an APK

Build a release APK:

```powershell
flutter clean
flutter pub get
flutter build apk --release
```

The APK is created at:

```text
build/app/outputs/flutter-apk/app-release.apk
```

Copy that APK to the phone, open it, and allow installation from the file manager when Android asks. For a public release, create a signing key and configure release signing in `android/app` before distributing the APK. Do not distribute an unsigned or debug APK as a production application.

For smaller downloads by device architecture, build split APKs:

```powershell
flutter build apk --split-per-abi --release
```

### Option C: Install from Google Play

For Play Store distribution, create a signed Android App Bundle:

```powershell
flutter build appbundle --release
```

Upload `build/app/outputs/bundle/release/app-release.aab` to Google Play Console, complete the store listing and testing requirements, then publish the release. Configure Firebase with the release certificate SHA-1 and SHA-256 in addition to the debug fingerprints.

## Install on an iPhone

iOS development requires macOS, Xcode, an Apple ID, and an iPhone connected by USB or the same development network.

1. On a Mac, install Xcode and run `flutter doctor`.
2. From `civic_haven`, run `flutterfire configure` and select **iOS**.
3. Open `ios/Runner.xcworkspace` in Xcode.
4. In **Signing & Capabilities**, select your Apple development team and set a unique bundle identifier.
5. Connect and trust the iPhone, then select it as the Xcode run target.
6. Run:

```bash
flutter pub get
flutter run
```

The iOS project already declares camera, location, and photo/file usage descriptions in `ios/Runner/Info.plist`. The user must still approve those permissions on the device.

For App Store or TestFlight distribution, use Xcode's **Archive** workflow or run `flutter build ipa --release`, then upload the signed build through Transporter or Xcode Organizer.

## Troubleshooting

- **Firebase placeholder credentials:** Run `flutterfire configure` from the project root and restart the app.
- **`flutter` is not recognized:** Add Flutter's `bin` directory to PATH or use `..\flutter\bin\flutter.bat` from `civic_haven`.
- **No Android device appears:** Enable USB debugging, install the device's USB driver, reconnect the cable, and run `flutter devices` again.
- **Reports do not save:** Confirm that Authentication, Firestore, and Storage are enabled and that the signed-in user has permission under the Firebase rules.
- **Camera or location does not work:** Check the phone's app permissions and test on a physical device.
- **iOS build fails on Windows:** iOS builds require macOS and Xcode.
